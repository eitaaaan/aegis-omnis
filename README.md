# S-01 Aegis Omnis

**プログラミング未経験からAIコーディングのみで開発した、ローカル動作のLLMアシスタント。**  
クラウド不使用・CPU環境（Ryzen 7 5700U / RAM 32GB）で稼働。現在 v131.0。

---

##  概要

難解な技術・概念を日常言語に翻訳することをコンセプトに、RAG・エージェント・ゲームAIを単一のPythonファイルに統合したローカルLLMアシスタントです。
- **開発の動機**
   歴史学を学ぶなかでウィトゲンシュタインの「生活形式」概念に出会い、ひとつの問いを持った。「AIは生活形式に参加できるか」。
   言語ゲームは身体・時間・他者との共同生活に埋め込まれている。ならばAIは、言語の駒を動かせても、ゲームの外側にいるのではないか。
    その問いを検証する方法は、自分でAIを作ることだった。開発を進めるうち、気づけば自分がプログラミングという生活形式に参加していた。問いは今も続いている。

- **開発期間**: 27日(2026/5/24現在）（環境構築含む）
- **開発手法**: AIコーディング（Claude / Gemini 無料枠のみ）
- **総コード量**: 11,000行超（Python シングルファイル）
- **動作環境**: CPUオンリー / クラウド不使用

## 🔧 主な技術的特徴

### 5段階 Advanced RAG パイプライン

ヘーゲルの弁証法をアーキテクチャの設計思想として体現。テーゼ（クエリ）→アンチテーゼ（多軸検索）→ジンテーゼ（統合・精錬）という処理フローで、精度と速度を両立します。現在も継続開発中。

```
[クエリ]
  ↓ ① HyDE（仮想ドキュメント生成でベクトル検索精度を向上）
  ↓ ② ChromaDB ベクトル検索（意味的類似性）
  ↓ ③ BM25 キーワード検索（完全一致）
  ↓ ④ RRF 融合（k=60、論文推奨値でランク統合）
  ↓ ⑤ Cross-Encoder Rerank（ms-marco-MiniLM-L-6-v2 で最終スコアリング）
[出力]
```

### 速度最適化（v130.6 Speed Pack）

CPU環境での応答速度を改善するため、11項目の最適化を実施した。

| 施策 | 内容 |
|------|------|
| `num_ctx` 半減 | 4096に削減しKVキャッシュコストを低減 |
| HyDE並列化 | Web取得と同時実行し、ブロッキングを除去 |
| RAGプリフェッチ | ユーザー入力直後にバックグラウンドでWeb取得を開始 |
| 8文字バッファ書き出し | 毎トークンflushを廃止し出力効率を改善 |
| 状態ファイルキャッシュ | TTLを5秒→30秒に延長し不要な再読み込みを削減 |

### モデル自動3段階選択

入力の複雑度をキーワードベースで推定し、モデルを動的に切り替える。

```
挨拶・短文  → gemma3:1b（高速）
標準的な質問 → gemma3:4b（バランス）
哲学・長文  → gemma3:12b（高精度）
```

### ゲームAI パフォーマンス改善（v130.6）

継続的なプロファイリングとデバッグで、以下の改善を実施しました。

| 対象 | 改善内容 | 効果 |
|------|----------|------|
| 将棋 `_find_king()` | O(81)全走査 → `_king_cache` でO(1)に変更 | **約80倍高速化** |
| 将棋 `legal_moves` | 同一局面での冗長計算を `_legal_cache` でキャッシュ | **約3倍高速化** |
| 将棋 `choose_move()` | タイムアウト上限を追加（Mid:3s / Hard:5s / VeryHard:8s） | depth=4での手数爆発によるフリーズを根絶 |
| 麻雀 ウォッチドッグ | クレーム待ちフェーズに18秒タイムアウトを実装 | 永久凍結を根絶 |
| 麻雀 `aiTurn()` | レースコンディションを即時キャプチャに修正 | ターン消滅バグを解消 |

### セキュリティ設計

| カテゴリ | 実装 |
|----------|------|
| プロンプトインジェクション防御 | 3層構造: XMLタグ無効化 → 役割変更パターン正規表現除去 → ゼロ幅文字除去 |
| SSRF防御 | プライベートIPレンジ全域 + IPv6マップドアドレスまで検査。リダイレクト先も再検査 |
| ASTベース電卓 | `eval()` 不使用。ホワイトリスト外ノードを拒否 |
| スレッドセーフ | ベクトルDB / HyDEキャッシュ / IDインクリメントに `threading.Lock` 適用 |

## ⚙️ 技術スタック

| 領域 | 技術 |
|------|------|
| LLMバックエンド | Ollama (gemma3:1b / 4b / 12b) |
| ベクトルDB | ChromaDB |
| RAG | BM25 (rank-bm25), sentence-transformers (Cross-Encoder), HyDE |
| 並列処理 | asyncio, threading, ThreadPoolExecutor |
| ゲームAI | Negamax + TranspositionTable（将棋）, MCTS（チェス）, curses UI |
| 動作環境 | Ryzen 7 5700U / RAM 32GB / CPUオンリー |

## 🚀 セットアップ

```bash
# 1. Ollama をインストールしてモデルを取得
ollama pull gemma3:4b 

# 2. 依存ライブラリをインストール
pip install chromadb rank-bm25 sentence-transformers python-dotenv

# 3. 起動
python3 new_main_v130.6.py
```
